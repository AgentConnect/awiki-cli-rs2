# File Size Exceptions

Rust source files should stay at or below 1200 non-generated lines by default. Exceptions require a corresponding oversized Go source file and a documented reason. A genuinely special file may be relaxed up to about 5000 lines when justified, but exception use must remain rare rather than becoming the normal module shape.

| Rust path | Rust lines | Go path | Go lines | Reason |
| --- | ---: | --- | ---: | --- |
| `crates/awiki-cli/src/runtime/listener_supervisor_run.rs` | 2304 | `awiki-cli/internal/runtime/listener/server.go` | 1802 | Foreground listener execution currently mirrors the oversized Go supervisor file for traceable 1:1 translation of run/service-run startup, bridge ownership, WebSocket session loops, secure notification normalization, local secure ACK recovery, queued local notification ownership/flush, queued secure outbox flushing, secure backlog replay, direct/group incoming contact lookup wiring, bridge-created session bootstrap waiting, real notification ping-loop wiring, bridge RPC reuse of the active session WebSocket through a single-reader RPC channel, secure backlog polling through that shared session RPC channel with Go's 15-second sync timeout boundary, secure E2EE client factory RPC reuse for notification normalization/ACK/outbox paths, listener-connect secure prekey retry through Go's non-session publisher path, and the live session-owner shutdown/reader-error status path. This is an intentional translation-time exception; splitting this runtime owner into smaller Rust files is a later optimization/refactor task, not mixed into the parity slice. New helper behavior should stay in smaller modules where practical; secure replay wiring reuses existing helper modules instead of carrying duplicate inline parsing/scanning logic, bridge-created sessions reuse the Supervisor host-notify sink and local-notification queue through small helpers, bridge bootstrap waiting uses `listener_bridge_runtime.rs` for one-shot signal/wait semantics rather than growing this file with another state machine, foreground OS signal shutdown handling lives in `listener_shutdown_signal.rs`, WebSocket pending-dispatch helper state lives in `listener_wsclient.rs`, WebSocket poll-read timeout and shutdown-aware ping support lives in `listener_ws_transport.rs`, local notification queue/flush primitives remain in `listener_local_notifications.rs` and `listener_local_notification_flush.rs`, and prekey retry decision algebra remains in `listener_session_loop.rs`. |
